    MikroTik Manager 1.1 (release candidate)¶

    1.1 is in release candidates on the dev branch and the :beta images (release channels): its features are complete, and only fixes go in from here. For stable, stay on 1.0 below.

    What's new in 1.1¶

    Everything 1.1 adds beyond the latest 1.0.x, for anyone coming from 1.0. Fixes aren't listed here; the beta entries below have every change, release by release.

    New¶

    Firewall zones (Zones)

    • Group a router's interfaces into zones and set what may pass between each pair, in a matrix; the manager writes and keeps the RouterOS rules, under Change Guard with Review changes.
    • Presets to start from: home or small office, an office with a guest network, a management network, or servers in a DMZ.
    • Custom rules in a zone pair can name ports, addresses, hostnames, ICMP of one type, or any IP protocol by number. NAT rules can name the WAN interface.
    • Log drops per zone, capped at 5 a second so logging can't overload a small router, and Log on a rule (or Log some of it on an allow-all pair) for what a zone accepts.
    • Zones can limit what the manager itself reaches on the router to the API, API-SSL and SSH ports.
    • With zones on, the Firewall tab reads as zones; the chains and jumps behind them are under Show RouterOS rules.
    • Zones work on routers without FastTrack offload.

    Firewall (Devices)

    • Quick rules: common protections in one step, including brute-force protection, which bans an address after repeated failed logins and shows bans across the fleet on the Security page. Management access adds the manager's own address.
    • The IPv6 firewall can be edited like IPv4: filter rules, NAT (RouterOS 7) and address lists, with reordering, counters and Review changes.
    • A rule that logs gets a short tag in its log prefix, so Firewall Logs can say which rule logged a line; rules that would read the same show their tags.
    • Known RouterOS CVEs count in a device's hardening score.

    Firewall Logs and Sessions, now under Security (Firewall logs, Sessions)

    • Firewall Logs opens grouped: one line per device, rule, interfaces, protocol and port, with counts. Raw shows every line.
    • It reads in zones, with zones as coloured badges, and filters From any zone and To any zone.
    • A period (1 hour to 30 days), an All rules filter for one rule's lines, and Hide rules for everything but the rules you pick.
    • An Application column naming the service behind each port, with row colours for DHCP and multicast. Port names, ranges and colours are set under Settings → Firewall Logs.
    • Resolve names shows client hostnames and reverse DNS in place of addresses.
    • The Firewall tab can show only the rules that log.
    • Sessions: one row per connection from NetFlow, with the client, server, NAT, bytes each way and how it ended.
    • Routers behind NAT are told apart in NetFlow, so their flows aren't lumped together.

    Traffic (Traffic analytics)

    • Click an application to see the clients behind it, each with its share, and Where it goes: its destinations and Top Destinations.
    • Names behind addresses, from the DNS query logs of AdGuard Home or Pi-hole (Settings → DNS Query Log), including AdGuard Home as a Home Assistant add-on.
    • Port names from Settings → Firewall Logs name Traffic's applications too.
    • Drag across a chart to zoom the whole page into that window.
    • Graphs as rates (bits and packets per second) rather than totals, under Settings → General → Appearance.
    • A new layout: Top Talkers beside Traffic by Application, with Top Destinations below.

    Network services (Network services)

    • Tunnels & PPP: the state of every IPsec peer, PPPoE server and client, PPP session, and EoIP, GRE and IPIP tunnel, problems first, with a Tunnel down alert. PPP Users and Sessions reads a router live: disconnect a session, and turn a PPP user or a PPPoE server off or on.
    • Netinstall from a router running RouterOS's netinstall package: install the package, entries that name the device to install, the package cache, and starting an install.
    • MLAG: each pair's state and role, the peer link, settings that differ between peers, and heartbeat and host-sync storms from the logs, with an MLAG degraded alert.
    • Routing rules on a device's Routing tab, in order, with what each one looks up.
    • DNS over HTTPS on Network Services → DNS.
    • WireGuard: a peer's client .conf and QR code, and Add Peer can generate the client's key pair.
    • DHCP, DNS, NTP and PPP open on the device when a site has only one.
    • Reverse proxy rules on routers, with Let's Encrypt certificates for public hostnames, on a new tab of Operations → Certificates (Device certificates).

    Switching, VLANs and bridges (Devices)

    • VLAN interfaces can be added, edited and removed from the VLANs tab, with addresses, and a change to the one the manager reaches the device through is predicted as a lockout.
    • Q-in-Q (a bridge's VLAN tag type, and a port's tag stacking) and MVRP, on bridges, bridge VLANs (forbidden ports) and VLAN interfaces.
    • A bridge's addresses can be edited from the Bridges tab, and EoIP, wireless, VLAN and other interfaces not on the faceplate can be added to a bridge.
    • Spanning tree you can set: a Spanning Tree card on the topology page for every tree in view, and each bridge port's priority, path cost, edge, point-to-point, BPDU guard and restricted role and TCN.
    • A bridge's MTU can be set, and a port's MTU form says the most its hardware takes.
    • 802.1X on switches and routers: ports that authenticate clients, with RADIUS from User Manager or your own server (802.1X, User Manager).
    • Drawn ports on the faceplate (RJ45 jacks, SFP cages, QSFP), sized to the device with its model name, virtual interfaces in a box of their own, and ports per row remembered per device.
    • Config Health finds access ports left tagged in other VLANs.

    Device pages (Device tabs)

    • A Graphs tab: history for every chart over one range (1 hour to 30 days), with a shared hover cursor, interfaces, connections, NAT, firewall drops and per-core CPU (Device graphs).
    • Peaks and drops: CPU and memory peaks as a band above the 5-minute average, and dropped packets counted.
    • A Firmware tab for the RouterOS and RouterBOOT check and install.
    • Torch in Tools: who is talking on an interface right now, flow by flow, narrowed by address, port and protocol.
    • An SMS inbox on the LTE tab, and the data-cap rule can delete the carrier's replies to its reset SMS (Cellular).
    • A Wireless Systems device type for outdoor PTP, PtMP and CPE radios, with an Antenna Aligner tab: live signal from one or both ends of a link and an optional tone (Antenna aligner).
    • Backups over the API when SSH is off, on RouterOS 7.13 and later (Backups).
    • Force add without checking connectivity in Add Device, for a device that isn't reachable yet.
    • The Configuration changed alert says what changed, as a diff.

    Wireless and CAPsMAN (CAPsMAN)

    • Set up CAPsMAN on the Wireless page: a controller and its access points, on both bands or one, with a 5 GHz SSID of its own if you want one, on wifi and legacy CAPsMAN.
    • A controller with radios of its own shows as Controller and AP.
    • AP Radio TX Retries remembers the band you picked.

    Topology (Topology)

    • Curved links leaving the bottom of one card and entering the top of the next, with Links to switch back to straight lines.
    • A tiered layout with the gateway on top, then core, access and APs, drawn top-down or left-to-right, and Arrange to lay the cards out again.
    • A Compact view of icons with a role chip (Gateway, CAPsMAN, CAP, STP root).
    • Port labels on links, short port names, bonds shown at both ends, and parallel links over VLAN, VRRP or bond interfaces merged into one with a +N.
    • Links heard over tunnels drawn dotted; links from OSPF neighbours, for routers reached only over tunnels.
    • Hosts that send LLDP without a name collapse into one N hosts chip.
    • Your own firewall, ISP modem or other gateway as a node on top of the map.
    • Export the whole map as PNG or SVG.
    • Display holds the Cards, Links, Layout and Port labels choices in one place.

    Clients and sites (Clients, Sites)

    • Client columns can be hidden and resized.
    • Clients leaves out the manager's own network devices, and switches, routers and access points it doesn't manage.
    • Connection Path goes from a client's device all the way to the top of the site.
    • A site can be placed on the map by latitude and longitude, and has its own map zoom, used wherever its devices show; the sites map opens on the default site.

    Dashboard

    • A readable Capacity & health card: busiest devices first, shared name prefixes shown once, 24-hour CPU graphs, and each metric opens its device graph.

    Operations and the manager itself

    • Jump hosts: reach devices through an SSH connection to another router, with RouterOS's reason when forwarding is off.
    • Scheduled bulk commands, once or repeating (Bulk commands).
    • A template from a device: start a command template from a device's configuration (Templates).
    • AI connections: read-only fleet review for AI tools over MCP or OpenAPI, with a token or your identity provider (AI connections).
    • Let's Encrypt certificates for the manager (Let's Encrypt).
    • 12- or 24-hour time, as a fleet default and per account (Time display).
    • Appearance: a System theme that follows your computer, seven accent colours or your own, and Midnight dark surfaces (Appearance).
    • Source builds behind a network proxy (HTTPS_PROXY).
    • Settings tabs can be linked to and stay put on reload.
    • User Manager is in the sidebar only where a device runs it.

    Scale and reliability (Polling and scaling)

    • Polls no longer stall on large networks: clients are written in batches.
    • A device is marked offline only after a number of missed polls in a row (Missed polls before offline, 2 by default); when most of a site goes quiet at once there's one alert for the site; and a reboot the manager sent, a rollout step or a maintenance window doesn't alert.
    • Device Logs and Firewall events open quickly on large log tables.
    • New major versions underneath: Express 5, BullMQ, openid-client 6, recharts 3, zustand 5 and TypeScript 6, and property-based fuzz tests on code that reads outside input.

    Changes you may notice¶

    • Who sees Settings. Admins change everything. Fleet operators see every Settings tab read-only (SSH Keys apart) and can no longer change alerting, webhooks, report schedules or clear the poll queue; write API tokens, which act as an operator, lose them too. Viewers and accounts limited to particular sites see only their own account (Who sees Settings).
    • Netinstall and scheduled commands need an admin. Netinstall changes need an admin for the router's site, and a scheduled bulk command runs only while the account that made it is still an admin (Netinstall, Bulk commands).
    • Menu: Firewall Logs and Sessions moved under Security.
    • Zones fold their rules away. With zones on, a device's Firewall tab reads as zones; the chains and jumps that carry them out are behind Show RouterOS rules.

    Upgrading from 1.0¶

    1. Update to the latest 1.0.x first if you can, then take a platform backup (Settings → Backup & Restore).
    2. Get the 1.1 compose file as well as the images, and keep your .env (Updating and image versions). A 1.0 compose file with 1.1 images also starts, so an update half done isn't stuck.
    3. Start it. Database migrations run on their own. PostgreSQL and Redis restart once, because 1.1's compose file pins newer builds of their images (still PostgreSQL 15 and Redis 7).

    Going back to 1.0 means restoring that platform backup: migrations only go forwards.

    Every security fix made during 1.1 also shipped on 1.0.x, so an up-to-date 1.0 install already has them (1.0 release notes).

    1.1.0-rc.4¶

    The fix in 1.0.32 below.

    • Downloads through a router with a private WAN address are counted for the right client. A router behind an ISP modem or CGNAT (its WAN address 192.168.x, 10.x or 100.64.x) had nearly all of its downloads shown in Traffic as Unattributed (local), while uploads went to the right clients. Downloads are recorded at the WAN, addressed to the router, and the LAN client was taken from the post-NAT address only when the WAN address was public. It is now taken whenever that address is local. Traffic already recorded stays where it is. The Traffic page docs now say what Unattributed (local) means (Discussion #486, from @godlessmind).

    1.1.0-rc.3¶

    The security fix and hardening in 1.0.31 below, from an outside review of rc.1.

    • Viewers and read-only API tokens could read command output, which can contain secrets (GHSA-rr75-cq8g-v6gq). What each device printed for a command run, and the run's CSV export, needed only viewer access, and only {{secret:...}} values were masked in it. A run that printed Wi-Fi or WireGuard keys showed them to accounts that see •••••••• everywhere else. Output is now for operators and admins; viewers see each device's status and errors, with a note saying why. If viewers or read tokens may have read such a run, consider changing those secrets.
    • Removing one device's SSH key could remove another's. The match was on the start of the key's comment, so revoking device 1's key also took device 12's, which then lost SSH. It now matches that device's keys only.
    • Changing your password, and setting up or turning off two-factor, have a limit per account (10 tries per 15 minutes), so a stolen session can't keep guessing the account password. The two-factor lockout counter can no longer be left without an expiry by a restart.
    • Smaller hardening: scripts, styles and images carry the same security headers as pages; a negative or non-numeric ?limit= gets the default instead of an error; only admins are told the admin account still has its default password; the username in the SSH key import is quoted.

    1.1.0-rc.2¶

    The fix in 1.0.30 below.

    • Devices that get their updates from the package mirror now show them everywhere. The Firmware page knew the mirror held a newer version for a device, but the Dashboard, the device list, the device's Firmware tab, alerts and reports only went by the device's own check with MikroTik, which finds nothing on a switch with no internet. They now count the mirror too, within about ten minutes of a sync, in Dark Site Mode as well. Install & Reboot on such a device says to upgrade it with a mirror rollout instead of calling it up to date (Local package mirror). Thanks to @ddavehauser for #482.

    1.1.0-rc.1¶

    The first release candidate for 1.1. Nothing new goes in from here, only fixes: please run it as you would a stable release and open an issue for anything that's wrong. What 1.1 adds is above. Since beta.75:

    • An RC install is told about the next RC. The update notice compared release candidates with stable, as it did for 1.0's, so a 1.1 RC wouldn't have heard about rc.2. RCs now compare with dev, and their images get a version tag (:1.1.0-rc.1) as betas do (Release channels).
    • The docs, checked against 1.1: the device tabs as they are now (802.1X, Bandwidth, Firmware, Antenna Aligner, and Torch in Tools), Settings paths that had drifted, who can change alerting, DNS query logs and platform backups, and the adoption sweep, which has no button: it's POST /api/adoption/cleanup.

    1.1.0-beta.75¶

    The fixes in 1.0.29 below, two of them security fixes, and more hardening from the 1.1 security review.

    • A long version string from a device could stall the manager (GHSA-vf5h-hmmw-67wq), site-limited operators could rename neighbours on other sites' maps (GHSA-3cq7-qcrg-vqj5), and RouterBOOT upgrades said a device didn't restart when it had, from Steven Wilton (@eskyuu) on #481: see 1.0.29.
    • More hardening: URLs and paths lose their trailing slashes without a regex that slowed on long runs of them; firewall zone names such as constructor are only ever names; and three more log lines can't be given extra lines by what they quote.

    1.1.0-beta.74¶

    A security fix, also in 1.0.28, and tighter roles, both from the 1.1 security review.

    • Accounts limited to some sites saw, and could rearrange, other sites' parts of the map (GHSA-97cq-mgp7-9p5f): the fix in 1.0.28 below.
    • Settings by role. Admins change settings. Fleet operators now see every Settings tab, read-only, apart from SSH Keys. They can no longer change alerting rules and channels, webhooks or report schedules, or clear the poll queue: those are admin-only now, for write API tokens too, since they act as an operator. Viewers, and accounts limited to particular sites, see only their own account in Settings: time format and password.
    • Netinstall changes need an admin. An install wipes whatever netboots on that network, so installing or removing the package, entries, the cache and starting an install need an admin for the router's site. Operators and viewers see the page read-only.

    1.1.0-beta.73¶

    • AP Radio TX Retries says why it's empty under legacy CAPsMAN: the fix in 1.0.27 below, from Ron on #470.

    • Downloads through a router with a private WAN address are counted for the right client. A router behind an ISP modem or CGNAT (its WAN address 192.168.x, 10.x or 100.64.x) had nearly all of its downloads shown in Traffic as Unattributed (local), while uploads went to the right clients. Downloads are recorded at the WAN, addressed to the router, and the LAN client was taken from the post-NAT address only when the WAN address was public. It is now taken whenever that address is local. Traffic already recorded stays where it is. The Traffic page docs now say what Unattributed (local) means (Discussion #486, from @godlessmind).

    1.0.31¶

    Released on Saturday 21 November 2026. A security fix, and hardening from an outside review of 1.1; update soon if you have viewers or read API tokens.

    • Viewers and read-only API tokens could read command output, which can contain secrets (GHSA-rr75-cq8g-v6gq). What each device printed for a command run, and the run's CSV export, needed only viewer access, and only {{secret:...}} values were masked in it. A run that printed Wi-Fi or WireGuard keys showed them to accounts that see •••••••• everywhere else. Output is now for operators and admins; viewers see each device's status and errors, with a note saying why. If viewers or read tokens may have read such a run, consider changing those secrets.
    • Removing one device's SSH key could remove another's. The match was on the start of the key's comment, so revoking device 1's key also took device 12's, which then lost SSH. It now matches that device's keys only.
    • Changing your password, and setting up or turning off two-factor, have a limit per account (10 tries per 15 minutes), so a stolen session can't keep guessing the account password. The two-factor lockout counter can no longer be left without an expiry by a restart.
    • Smaller hardening: scripts, styles and images carry the same security headers as pages; a negative or non-numeric ?limit= gets the default instead of an error; only admins are told the admin account still has its default password; the username in the SSH key import is quoted.

    1.0.29¶

    Released on Friday 20 November 2026. Two security fixes from the 1.1 security review, and a RouterBOOT fix from Steven Wilton (@eskyuu); update soon.

    • A long version string from a device could stall the manager (GHSA-vf5h-hmmw-67wq). The poller compares the RouterBOOT versions a device reports before storing them, and the parser slowed with the square of their length: 200,000 characters held up the web UI, API and polling for about 19 seconds. Real RouterOS doesn't send such a thing, but a fake RouterOS API server added as a device could. Version strings are now cut to 64 characters before they're read.
    • Site-limited operators could rename neighbours on other sites' maps (GHSA-3cq7-qcrg-vqj5). The part of 1.0.28's fix that was missed: the name and type of a discovered neighbour, which show on every site's map. A site-limited account now names only the neighbours on its own part of the map.
    • RouterBOOT upgrades said a device "didn't restart when asked (twice)" when it had. The check compared uptime with a reading taken just after the first reboot, so a device that took longer than that to come back from the second looked like it never went down. It now counts the time since that reading, and a changed bootloader version also proves the restart. Thanks to Steven Wilton (@eskyuu) for #481.
    • Hardening from the review: pasted certificates are read in linear time (a 10 MB field of BEGIN lines took a long while), and generated command secrets use every character equally often.

    1.0.26¶

    Released on Thursday 19 November 2026. Performance on large fleets, all from @JohnDepon, who measured MikroTik Manager polling 126 devices and fixed what held it back, one cause at a time. On that install the database went from about 365% CPU to 13%, and polls stopped timing out and marking healthy devices offline.

    • The Clients list and counts no longer spend seconds compiling. Postgres compiled every client query (JIT) for about 2.7 s before running it in 0.1 s. It's off for the app's connections (#471).
    • Pages refresh on their own timers, not on every device poll. The Dashboard, Clients, Events and Firewall Logs refetched their heaviest queries each time any device was polled, several times a second on a big fleet. They refresh every 30 to 60 seconds, as before (#473), and the Dashboard's wireless count asks for the total alone (#478).
    • Less work per poll: the fleet and site client totals are counted once every 15 seconds in one query (#474); a device's clients are stored in one statement (#475); a client whose MAC has no known vendor isn't looked up again every poll (#476); and log times are read with far fewer time zone lookups (#472).
    • The clients table stays small. An index nothing needed made every client update write to every index and leave dead rows behind. It's dropped, and the table leaves room on each page so updates stay in place (#477). This runs once when the backend starts after the update and takes well under a second.
    • The site list is as wide as its longest name, so long site names aren't cut to a few letters, with the device counts lined up and the full name on hover (#480).

    1.0.13¶

    Released on Monday 9 November 2026. Updates are safer for the databases.

    This update restarts Postgres, Redis and InfluxDB once, because their settings changed. Your data stays as it is.

    • Redis repairs a damaged data file instead of refusing to start. If Redis's append-only file is damaged, for example because the disk lost a write in a power cut or a hard reset, Redis wouldn't start, and the whole manager waited for it. This happened on a production install: the damage sat unnoticed for a day, because Redis reads the file only when it starts, until an update restarted it. The file is now checked before Redis starts and, if it's damaged, repaired with Redis's own tool, which cuts it at the last good record. Redis holds only the job queue, which refills itself, so nothing else is lost. A copy of the damaged files is kept, and Redis's log says what happened. See The databases during an update.
    • Postgres, Redis and InfluxDB get 60 seconds to stop cleanly when an update or a restart stops them, instead of Docker's 10, so none is cut off mid-write.
    • A Redis password with quotes or $ in it broke Redis's health check. The password now reaches Redis and the check through the container's environment instead of being pasted into a shell command.

    1.0.12¶

    Released on Monday 9 November 2026. Clients that stayed online, mirror rollouts on small switches, and the CRS354's QSFP+ ports.

    • Clients stayed online long after they'd left (#363). RouterOS keeps stale and failed ARP entries, MAC and all, for days on a quiet VLAN, and any that wasn't failed counted as the client being there, so phones stayed online all weekend. Only entries the router is in touch with count now (reachable, delay, probe, or static). A stale one keeps a client that's already online for 15 minutes, so a quiet printer doesn't flicker, but never brings one online. Thanks to aziz for tracking down the cause. See Clients.
    • Mirror rollouts refused switches with 16 MB of flash. A device such as a CRS309 or hAP ac² runs from RAM and downloads packages into RAM, but the rollout measured them against its free flash, about 3 MB, and stopped with "Not enough space". It checks free memory on those devices now, keeping a margin for the device itself. Reported by Manuel in Discussion #85.
    • The CRS354's QSFP+ ports drew as eight separate cages. The CRS3xx names its QSFP+ lanes qsfpplus1-1 to qsfpplus2-4, which didn't fit the lane naming the faceplate knew, so each lane was a cage of its own (Q1, Q1, Q2, Q2 and so on). They're two cages of four lanes now. Also reported by Manuel.

    1.0.11¶

    Released on Sunday 8 November 2026. Trunk ports and their native VLAN.

    • A trunk port dropped untagged traffic. Setting a port to trunk wrote frame-types=admit-only-vlan-tagged, so the native VLAN the port editor offered never applied: a laptop, printer or unmanaged switch plugged into a trunk port couldn't talk at all. A trunk now accepts both kinds of frame. Tagged frames go to its tagged VLANs, and untagged frames join the native VLAN, which the port carries untagged. Tick Tagged only for a trunk that should drop untagged frames, as before. Saving a trunk also takes the port out of any untagged VLAN other than its native one. Trunks saved by older versions open with Tagged only ticked and keep working as they did until you untick it and save. See Changing a port's VLAN.

    1.0.7¶

    Released on Saturday 7 November 2026. Housekeeping: restore points left on devices, Postgres's shared memory, and two development-only dependency alerts.

    • Old Change Guard restore points are cleared from devices. Each guarded change saves a restore point (mtm-rp-….backup) that only its revert scheduler reads. They were left behind when a revert fired, when the manager restarted mid-change, or when the clean-up couldn't reach the device, and piled up in the device's files. After each change, Change Guard now removes any restore point whose revert scheduler is gone, in binary and script mode, and keeps one that's still armed (Change Guard).
    • Postgres gets 256 MB of shared memory (shm_size in both compose files). Docker's default is 64 MB, and on a large events table Postgres's parallel queries and parallel VACUUM could fail with could not resize shared memory segment … No space left on device. If you keep your own copy of the compose file, add shm_size: 256m to the postgres service.
    • minimatch in the build and test tooling is updated to 11, clearing two Dependabot alerts. Neither it nor deepmerge (an alert with no fix yet) is in the images.

    What it does¶

    MikroTik Manager is a self-hosted manager for fleets of MikroTik routers, switches and access points on RouterOS 6 and 7.

    • Inventory and health. Devices grouped into sites and site groups, live status, resources, availability and reboots, hardware sensors, optics and PoE. Adoption of configured and factory-default devices. Devices, Sites, Adopting devices
    • Configuration from one place. Ports, bridges, VLANs (bridge, switch-chip and VLAN interfaces), IPv4 and IPv6 routes with routing tables, firewall and NAT, queues, wireless, DHCP, DNS, NTP, WireGuard, logging, SNMP and LLDP, bulk commands, templates and firmware rollouts in waves.
    • Change Guard. Every change that could cut the manager off is checked against the device's real management path first, and protected by an automatic revert if the device stops answering. Change Guard
    • Security. A posture check for every device (management services, firewall input rules, IPv6, RoMON, certificates), known RouterOS vulnerabilities in the fleet, device certificates from the manager's own CA, SSH keys, and fixes you can apply in one click. Security page
    • Clients, wireless and traffic. Client history and identification, roaming, Wi-Fi radios, RF health, rogue APs, guest Wi-Fi, CAPsMAN, NetFlow traffic analytics, firewall logs, LTE. Clients, Wireless, Traffic analytics
    • Operations. Topology from LLDP and spanning tree, configuration backups and diffs, alerting with webhooks and reports, maintenance windows, platform backup and restore, single sign-on, per-site roles, scoped API tokens and an audit log. Alerting, Backups, API and automation
    • Scale. A poller built for large fleets: batched reads, optional persistent sessions, separate worker processes, and a health view that says when it's falling behind. Polling and scaling

    Upgrading from a beta¶

    No settings need changing. Database migrations run automatically on startup.

    1. Take a platform backup first (Settings → Backup & Restore). It's cheap insurance.
    2. Update as you always have, including the compose file, not only the images (Updating and image versions):
      • from a git checkout: git pull, then docker compose pull && docker compose up -d (or docker compose up -d --build backend nginx if you build locally);
      • with the GHCR compose file: download docker-compose.ghcr.yml again, keep your .env, then pull and start.

    Release channels¶

    From 1.0 there are two channels (details):

    • Stable, the default: main and the :latest images. 1.0.x, fixes only.
    • Beta: dev and the :beta images. New features as betas of the next minor version.
